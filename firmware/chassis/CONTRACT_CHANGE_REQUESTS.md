# Contract change requests from the chassis firmware lead

Target: `interface/system/contract.yaml` (owner: integration lead). Nothing below has been applied to the contract; the firmware and `interface/chassis_icd.md` work without these changes and mark the affected points as proposals.

| # | Request | Why | Present workaround |
|---|---|---|---|
| CCR-CHS-01 | Raise the chassis link maximum record from 2048 to 4096 bytes (at least for responses). | The `STATE` content the contract lists is about 1.8 kB in a normal state (eleven ToF objects alone are 0.7 kB). With many reasons/flags it cannot fit; measured worst case with every list complete would be about 2.6 kB. | `STATE` is compacted with `"truncated":true` (ICD §3.4); the additive `DIAG` op carries the complete lists. |
| CCR-CHS-02 | Add the additive op `DIAG` to the chassis op table. | Complete reason/flag lists, E-stop pole readbacks, brake-test state, live causes (`sw_active`, `hw_active`). | Implemented as additive; a host that does not know it is unaffected. |
| CCR-CHS-03 | Define `REARM_SW.nonce` as "the `rearm_nonce` last reported by the chassis". | The table lists `nonce` without semantics. A chassis-issued value makes a cached/replayed re-arm unable to clear a later stop (Operator_Interface: never replay Start/Resume). | Implemented that way; `rearm_nonce` is in `STATE`, `DRIVE`, `STOP` and `REARM_SW` replies. |
| CCR-CHS-04 | Add a per-`op_mode` cap table (forward, reverse, yaw) to `motion`. | The contract gives one envelope; `SET_OP_MODE` "selects the speed/field profile" but no profile values exist. | Defaults proposed in ICD §6.1 as configuration keys `caps.*`, hard-limited to the contract envelope. |
| CCR-CHS-05 | Add to the `DRIVE` row: optional arg `issued_us`; response members `stationary`, `applied`, `motion`, `allow`, `v_cap_mps`, `hold`, `rearm_nonce`; and to `STOP`: optional `reason` for host-originated protective stops (`FIELD_FRONT/LEFT/RIGHT/REAR`, `HEAD_LINK`, `LOCALIZATION`). | `stationary` is the owner's step-and-count requirement; `reason` is the only way the host-side reasons of the `protective_stop_reason` enum can ever be set (the MCU has no front/side ranging). | Implemented as additive members. |
| CCR-CHS-06 | State in `chassis_link` that `HELLO` opens the controlling session and that motion-enabling ops are rejected (`NO_SESSION`) before it. | Makes "MCU reset ⇒ host must re-identify" enforceable. | Implemented; documented in ICD §1.3. |
| CCR-CHS-07 | Decide the pre-motion alert policy for `STEP_AND_COUNT`: idle time default 5 s (owner request) is shorter than the default station time (0.5 s + 10 s). | With defaults every hop gets the full 1.5 s alert. | `alert.rest_ms` is configurable up to 600 s; ICD §6.11 explains. Operating decision (RQ-051). |
| CCR-CHS-08 | Add `hw_inhibit_reason` value for "latch dropped, cause not identified" (or accept `VMOT_FAULT` for it) and a reason for "firmware stop escalation". | The enum has no entry for an unexplained drop or for ARM_PERMIT withdrawal after uncommanded motion. | `VMOT_FAULT` and `MCU_NOT_READY` are used, with the detail in the `PERMIT`/`HW_LATCH` events. |
| CCR-CHS-09 | Hardware: route the external watchdog output to NRST as well as into the chain, keep IOX_B out of the NRST domain, gate DRV nSLEEP with the latch (see `pinmap.yaml › hardware_requests`). | Firmware strategy assumes a watchdog timeout both opens the chain and resets the MCU. | Emulator models it that way. |
