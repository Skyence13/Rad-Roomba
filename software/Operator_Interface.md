# Technician interface and guided follow-up

**Revision 0.3 · proposed for prototype development.** The robot hosts a browser application on its onboard computer. Operators use the same page from a phone, tablet or laptop. The included `guide_demo.html` simulates a small review queue on one device. The production backend, interlocks, authentication and field hardware require implementation and qualification.

## Access and command authority

- Serve the interface and its assets locally. Support an approved site WLAN or a secured robot access point and offer an onboard label giving the robot ID and local address. A QR label can contain the address; credentials stay separate. Test name resolution, local TLS trust, direct IP fallback and signal quality at both ends of each trailer type with the doors secured.
- Apply named accounts or approved site identity, HTTPS and session expiry. Give viewers read-only maps, RP users authority to approve profiles and survey disposition, and operators authority to request mission commands. Limit a controlled run to one operator with a server-managed control lease. Choose a visible takeover/release procedure, so a second operator cannot silently redirect a moving robot. A physical E-stop remains available regardless of session or lease.
- The page receives connected status, heartbeat age, live telemetry and the run snapshot. Commands use authenticated, authorized requests to a narrow backend API, which checks the current run, state, selected head, target and motion interlocks before handing a command to ROS 2. Time-stamp and journal accepted and rejected commands. Give each command a unique ID and return the last committed result on a retry. Never replay Next, Resume or Start from a cached page or offline request queue.
- Suggested implementation: ordinary HTTP requests for commands and an event stream for run state. On reconnect, read the current server state and last acknowledged action before enabling controls. Implement cookie/session protections and request-forgery protection. Keep robot and ROS control interfaces within the onboard trust boundary. The design requires no native phone application. See [MDN event streams](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events) and [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

The charge inlet takes priority over the laboratory harness. When both are connected, select Charge/Service and inhibit acquisition, normal head heating and traction. Disconnecting the charge plug leaves the system inactive until deliberate setup.

## Operator views

| View | What the technician can see or do |
|---|---|
| Overview and preflight | Select vehicle and run, check the head/geometry/calibration association established at connection, energy and thermal margin, check-source and bumper checks, approved operating mode, local protective-field and hands-on inhibit state and the permitted staging/parking locations. A supervised test run uses a labeled commissioning mode. |
| Scan | Inspect progressive activity and coverage, qualified sensitivity, unresolved areas, pose quality, safety state, mission progress, communication age, holds and parking access. Pause, request stop or end a run under the applicable permissions. Show the last telemetry time during an outage. |
| Review flagged areas | See a stable list with hotspot ID, original time, response channel, footprint, original reading and uncertainty, coordinates and disposition. Select the first destination or request a validated route order before starting. Preserve independent findings that overlap rather than automatically merging exposure records. |
| Reports and settings | Retrieve reports, replay records and export data. Restrict profile/calibration edits to authorized roles. A running mission retains a snapshot of its original configuration. Charging/service mode permits access to settings and data with a persistent charge-connected indication and enforced drive lockout. |

## Local controls and indicators

| Control or indication | Operator action and design intent |
|---|---|
| Power switch or isolator | Clearly identify run/off and means of isolation for servicing or battery swap. Use a controlled shutdown to commit data before removing power during normal service. |
| Latching E-stop | Independent local drive inhibit. Resetting the mushroom permits a deliberate recovery sequence; it never restarts motion. Locate the button for immediate access during setup and bench trials. Validate an external stop/access approach for closed-door operation. |
| Start / Resume | Guard or recess the actuator. Enable only for an explicitly armed operating mode after its preflight, access and motion checks. Set a pre-motion indication and clearance period from the site risk assessment. Use deliberate start, rather than a radio reconnection or resetting an interlock, to resume a paused run. |
| Pause / Stop | Separate large labeled momentary control for a controlled motion hold. The interface provides the same normal request. A person can activate the latching E-stop for an emergency. |
| Status indicator | Example coding: Ready = steady blue, Moving = pulsing blue with a moving-pattern cue, Holding or awaiting Next = pulsing amber, Fault = flashing red, Charge/Service = steady white with charge icon. Use labeled icons/patterns as well as color. Provide a brief qualified pre-motion signal, and show the cause and safe next action on the operator page. A local compact text display is an optional aid. |
| Outside the closed trailer | Test any externally required stop/inhibit and alert transport at maximum range with doors secured; qualify the retained stop path for the approved operating mode. A web Stop command depends on an intact ordinary data link. Operator access and recovery must be possible if the link is unavailable. |

## People in the trailer

The target shared-space mode lets attendants remain in the trailer while the robot scans, visits hotspots, exposes the floor or returns to park. An attendant can stand alongside the route where there is sufficient room for the qualified protective field and a clear way out. The robot may move while people are present if the local protection for the commanded direction is healthy, the field is clear and the other motion permissions are satisfied. The interface distinguishes *someone is in the trailer* from *the robot must stop*. Any site control for an open elevated doorway still applies.

Use the actual robot, head, payload and floor to qualify the protective envelope for forward, reverse and turning motion. Include protruding head corners, possible occlusion and approach from beside a wall. Set the speed limits, protective distances and required reliability from the site assessment and measured stopping performance. Demonstrate the response to a person-sized test target, a foot/leg entering the path, a blocked escape route and failed sensing under representative winter conditions. Contact bumpers, drop sensors, navigation LiDAR and an E-stop are design inputs. Shared-space readiness requires verified protection for people. A narrow location with insufficient room for a person and the robot remains a hold or a deferred target. For the site risk assessment and protection concepts, see [CCOHS, Robots and Cobots](https://www.ccohs.ca/oshanswers/safety_haz/robots_cobots.html).

A boot, hand probe or other obstruction can cover the floor under a planned detector footprint. Preserve the raw counts, flag the affected footprint, and withhold exposure/coverage credit until the area can be scanned clear. Stop or skip the obstructed leg as needed, revisit it after clearance, and retain any unresolved area and reason in the report. Unreliable head location also prevents locating counts on the floor.

## Guided review sequence

1. Load the immutable survey, selected trailer datum and flagged footprints. Select **Review flagged areas** and the visit order. Register the stored map to the trailer, including after a restart or pack swap. Check the route, permitted speed and local clearance for the whole body and head.
2. Select **Next** from a permitted position, including inside the trailer in shared-space mode. The host accepts one transit to the displayed flag, aligns the original detector lane using its measured offset, and verifies arrival tolerance. Display the flag ID, coordinates relative to the door and wall, achieved offset and uncertainty.
3. At **At spot**, the robot remains parked until a new command. **Repeat** appends a distinct observation. **Expose spot** moves it through a checked route to a preplanned offset and displays how to find the original point with a hand probe. The same field protection covers this short move and **Park now**.
4. For work within reach of the detector, wheels or moving route, request a hands-on hold and positively inhibit traction. Verify the stopped, inhibited state by the prescribed local means before reaching in, taking a wipe, locating a hand probe beneath the head or handling the robot. A browser indication reports the state of the independent safeguard. A worker surveying an exposed point outside the protected envelope can remain there under the shared-space procedure.
5. When the hands-on task is complete, people and tools clear the motion envelope. Release the inhibit, deliberately restore motion permission and select the next destination. They can remain elsewhere in the trailer. A protective-field intrusion stops the current move. Clearing the field, releasing an inhibit or reconnecting a browser leaves the robot stationary. A fresh **Next**, **Expose spot** or **Park** is required for motion. Inhibited or duplicate commands cannot become pending moves.
6. An unavailable route, loss of head location or insufficient clearance leaves the flag unresolved. **Skip** records a reason. **Next · Park** after the last target sends the robot to the chosen parking point. Archive each command, operator, mode, interlock state, original observation, target and achieved location, time, uncertainty and follow-up disposition.

## Operating modes and holds

| Event | Shared-space scan or guided review | Commissioning and optional secured unattended mode |
|---|---|---|
| Attendant present outside the protected envelope | Motion can continue at the qualified speed. Show field health and whether the current direction is permitted. Manual close work has a separate inhibit. | Commissioning uses the protection and supervision specified for the trial. For a secured, empty unattended run, supervise the chosen independent access boundary. |
| Protective field occupied, sensing unavailable, or hands-on inhibit active | Stop or retain the local hold. Identify the cause. Clearing it permits deliberate rearm and a fresh command. | Apply the configured independent safeguards. An opened interlocked boundary in secured unattended mode stops motion. |
| Observer closes browser | The onboard mission and local protection continue. A guided move or supervised profile holds if its required control lease/link expires. | Commissioning holds on loss of its required supervisor. The optional unattended scan continues across ordinary viewer or Wi-Fi loss while required safeguards and recording remain healthy. |
| E-stop, cliff trip, critical bumper fault, MCU watchdog or required protective link failure | Locally stop/inhibit as specified for the fault, record the event and require deliberate recovery. | Same response. Provide the stop and retrieval arrangement for the chosen mode, including closed-door use. |
| Invalid head association, clock, position, acquisition or recording | Hold survey credit and apply the specified mission hold. Flag affected coverage. Resume only with valid data/registration and deliberate authorization. | Same response. Journal locally. Deliver faults and completion through the authorized notification route. |
| Restart, reset, mode change or restored link | An interruption that disabled traction needs positive rearm and a new motion command. Refresh the page from the actual run state. | Select the qualified mode in preflight. A state change cannot silently switch operating profiles. |

An unattended scan can be left running without a technician following it. Define the allowed occupancy, independent safeguards and response arrangements in the site’s approved profile. A shared-space scan with attendants nearby and a separately commissioned secured-empty scan each have distinct conditions. Assign fault response and retrieval responsibilities, and test alerts if the operation depends on them. Keep motion protection and durable logging onboard when the web service is unavailable.

## Acceptance exercises

1. Authenticate two PCs and a phone on a closed-container trial. Two read-only sessions can observe the same run. Only the current controlling operator can order motion. Verify deliberate takeover and an audit trail. A repeated request ID moves the queue once.
2. Shut the browser during a qualified unattended trial. The local recorder and motion/health checks continue. Reopen it and recover the same run ID, state and map. Remove required supervision during a commissioning run and verify the measured hold response. Independently interrupt the required safety link or access permit in an unattended run and verify the protective response.
3. Record several surveyed test markers on different detector lanes. Return in a changed order and opposite approach heading. Compare active-segment location against independent ground truth and the agreed tolerance; record misses, confidence and reasons. Exercise a seam, an inaccessible target, and a target at the wall.
4. Exercise a scan, Next, Expose spot and Park with the occupied area represented by test targets. A target outside the validated envelope permits travel. Entry into the protected field or an unhealthy channel stops motion. Apply the hands-on inhibit while parked, issue a duplicate or blocked Next, then clear the field and release the inhibit. No movement occurs until deliberate rearm and a fresh command. Check rotation, reverse travel and narrow routes. Move to attended trials only after measured protection meets the site criteria. Failed registration leaves a destination unresolved.
5. Connect the charge lead and try all local and web Start/Resume/Next paths. All drive requests are inhibited in Charge/Service while data and settings remain accessible. Disconnect the charger, restore the battery supply, and check deliberate rearm. Test indicator semantics with gloves, weak light, noise and a color-vision-independent observer.
