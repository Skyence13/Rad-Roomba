# RR-HEAD-ACQ rev A - detector-head acquisition board (stage 2 KiCad 9 project, stage 3 review fixes)

Generated by the scripted flow `tools/eda` (rrkicad) from the stage-1 net-level definition `design/circuit.py`.
Edit only the Python sources listed below; every KiCad file in this directory is regenerated.

| File | Role |
|---|---|
| `design/` | stage 1 (circuit.py, description, layout guidance) - **not edited**, reviewed baseline |
| `overrides.py` | override layer on circuit.py (IDs S2-xx, stage 3 S3-xx: NET / VALUE / ADD); `python3 overrides.py` prints the log, proves the pin-level diff is exactly the listed S3 entries and re-runs the stage-1 self-check on the overridden netlist |
| `libs.py` | project-local symbols / footprints (sources and UNVERIFIED marks in its docstring); shield-can geometry constants |

| `board.py` | the board definition the tool evaluates (import + libs + layout) |
| `STAGE2_CHANGE_REQUESTS.md` | deviations from stage 1 and requests to stage 1 / head mechanical |
| `scripts/` | `netcheck.py` (KiCad netlist vs circuit.py), `placecheck.py` (fast courtyard / wall / hole check), `legalize.py`, `placeplot.py`, `heightcheck.py`, `fpdump.py` / `fpinfo.py` / `symcheck.py` / `fpcheck.py` (library inspection in the KiCad container) |

## 2. Frame mapping

`board_envelopes.yaml` RR-HEAD-ACQ (u, v) = tool board frame (X, Y), no rotation, no offset: origin = rear-left corner seen
from above, X = u toward the robot's right (base_link -y), Y = v forward (base_link +x).
base_link = (83.2 + Y, 163.0 - X, 34.5 + z) mm (PCB underside at z 34.5).  The same coordinates are used by board.py,
the pick-and-place file, `out/pinmap.json` and the STEP model (`out/RR-HEAD-ACQ.step`, origin = board origin).

## 3. What is in the design

* **Schematic**: 1095 / 1095 records (1085 stage 1 + 10 stage 3), 31 A3 sheets: 8 board sheets + four identical lane sheet sets
  (LANEk_FLOOR, LANEk_FLOOR_2, LANEk_REF, LANEk_LOGIC, LANEk_LOGIC_2) + MECH.  DNP parts carry the KiCad DNP flag; every
  symbol carries value, footprint, MPN, Manufacturer, notes (verify flag where stage 1 or stage 2 could not confirm).
* **Stack-up (stage 3, review M6)**: 6 layers, 1.6 mm: **F.Cu sig / 0.10 / In1 GND / 0.15 / In2 sig / 0.97 / In3 PWR / 0.15 / In4 GND /
  0.10 / B.Cu sig** (`libs.STACK`, written by `libs.install_stackup_hook()` - the tool's fixed stack F / GND / sig / sig / PWR / sig is
  replaced from this directory, tools/eda not edited). F.Cu components + sensitive/HV routing + GND pour; In1 and In4 solid GND (BUS_GND island
  + barrier notch under J2 on both); In2 the only inner signal layer (HV drops, HVF links and the bias riser), 0.15 mm over In1; In3 power
  islands (+5V_A under the AFE strip v < 41.5, +3V3_EVT under each lane logic area, +5V6 under J1/REG, +3V3 elsewhere), typed "power" so the
  router does not use it, 0.15 mm from In4 GND; B.Cu signals (BUSY/ULD/ALPHA/LLD/CLR long runs) over the solid In4 GND, GND pour, no components.
  Every signal layer has a GND plane as its nearest neighbour; there is no broadside signal pair any more. Cost: 3 routing layers instead of 4
  (In3 carried 1035 routed items in the stage-2 run; B.Cu only 275).
* **Lane block** (lane 0 laid out, lanes 1-3 = `board.replicate()` copies at du = 87.5 mm): rear strip v 1.5..7.3 with
  F bias / F anode U.FL (du -15.47 / -10.38), JST GH-6 auxiliary (du -1.80), R bias / R anode (du +6.78 / +11.87);
  shield can v 8.25..40.25 with the HV filter cells, input networks, pulser switches, preamps, fast stages, clamps,
  comparators (and the floor slow path in the centre strip), all ICs at fixed positions (`layout.CH`, `CH_SLOW`);
  12 clips on the wall line; HV_BUS trunk at v 43 on F.Cu; lane logic v 45..67 (trim buffer, OR gates, latches,
  monitor mux, trim networks, pull-downs).  Placement rules enforced by `scripts/legalize.py`: lane-0 channel parts
  inside the can, trim networks and logic in the logic area, every copy collision-free, HV / heater pads >= 1.05 mm
  from pads of other nets.
* **Board blocks** (explicit ICs/connectors, passives frozen): J1 landing u 50..101 (J2601 + J2001 rear-facing, pin rows at v 17.57 =
  7 mm in from the rear edge (stage 3, IB-61), heater switch and power entry compressed into v 19..41 in front of them, H1 at v 30 with the
  frame bond F2801/R2801/R2802 and the J1 shield parts C2007/R2012/TP2004 around it), REG u 50..101 v 45..67, BIAS u 100..146 v 67..95,
  DACs u 143..178 v 47..53, MCU (LQFP-100, pin 1 rear-left) at (168, 77.5), monitor u 182..216, isolated RS-485 island
  u 230..272 v 0..13 with a 4 mm copper-free barrier (keep-out all layers) crossed only by U2501 / U2503.
* **Net classes**: HV (0.25 mm / 1.0 mm), HEATER (1.0 / 1.0), POWER (0.4 / 0.15), ISOLATED (0.4 / 0.25),
  DIFF (0.25 / 0.25), SENSITIVE (0.2 / 0.3), default 0.2 / 0.15.
* **Frame (stage 3, review M3)**: each hole pad is its own copper island (`FRAME` at H1, `FRAME_H2..H8`); bond parts sit at their hole and
  have a locked 0.6 mm F.Cu track into the hole pad (waived inside the hole keep-out: same net as the standoff). DC bond F2801 + R2801 at H1;
  10 nF at H2, H5, H6, H8 (not H3: inside the isolated island); J2 shield R2505/C2504/TP2501 at H3; `scripts/placecheck.py` enforces the distances.
* **Keep-outs**: 7.0 mm circles at the 8 holes (6.0 envelope + 0.5), mated-plug zone behind J2001/J2601 (`KO_PLUG_J1`, no footprints), shield-can walls on F.Cu (tracks + vias; mouse

## 5. Placement workflow (reproducible)

1. Explicit table in `layout.py` (connectors, ICs, HV cell, clamps, clips, can, holes).
2. Pass 1 (only when `layout_frozen.json` is absent): the tool auto-arranges the passives with `near=` hints to the pad of
   an explicitly placed part they connect to, with footprint keep-outs over the lane 1-3 blocks and around the lane-0 block.
3. Freeze: `[auto]` lines of `reports/placement.txt` for lane 0 + board level -> `layout_frozen.json`;
   `scripts/legalize.py` then moves every frozen part that violates the rules above to the nearest legal position.
4. Pass 2: normal build; lanes 1-3 are copies.

## 6. Waivers (tool-level, reasons in `reports/summary.json`)

* `clearance` between two pads of ONE component (U.FL centre pin vs shell, two-terminal HV / heater parts).
* `items_not_allowed` for GND copper (clip-pad fan-out) under the GND shield-can walls.
No unconnected item is waived.

## 8. Tool defects met (worked around in this directory; tools/eda not edited)

1. Local footprints need >= 1 pad: the pad-less shield-can footprint is swapped in by a hook on `locallib.make_footprint` (libs.py).
2. The importer only resolves STOCK symbol hints; rr_local symbols are passed per reference (`symbols=`).
3. Plane fan-out checks only its own net-class clearance (GND stubs/vias inside the 1.0 mm HV / heater clearance) and
   ignores footprint-internal rule areas (U.FL): via keep-outs in layout.py.
4. Auto-arranger: unaware of `replicate()` destinations; group-region slicing scatters board-level passives -> pass-1
   keep-outs + `near=` hints + scripts/legalize.py.
5. Parts whose footprint is excluded from the BOM (test pads, holes, fiducials, TC2030, solder jumper) give schematic-
   parity errors unless `bom=False`.
6. Automatic continue run crashes: `pcb._edge_guard` -> AttributeError 'SwigPyObject' object has no attribute
   'NewOutline' (stage_retrydsn) -> `retries=0`.
7. Replicated block vias coincide with fan-out vias of the copies (66 `holes_co_located` warnings).
8. `route(escape=..., finisher=...)` exist in model.py but are not documented in the README -> not used (escape=False).
9. (stage 3) The 6-layer stack-up and the plane layers are fixed in the tool (In1 GND / In2 sig / In3 sig / In4 PWR, 0.109 mm In2-In3):
   `libs.install_stackup_hook()` sets `board.plane_layers` = In1/In3/In4 and replaces `rrkicad.pcb._stackup` for this board only.
   Request to the tool owner: make the stack-up (layer roles and dielectric thicknesses) a Board() option.
