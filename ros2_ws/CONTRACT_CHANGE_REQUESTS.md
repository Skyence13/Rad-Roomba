# Contract change requests from robot software (ros2_ws)

Owner of the contract: integration lead. Nothing in `interface/system/`, `docs/architecture/`
or the ICDs was edited by robot software. Each item states what the software does today.

| ID | Subject | Request | What ros2_ws does now |
|---|---|---|---|
| CR-01 | `SYNC.expiry_us` semantics (head ICD §4) | **Closed by `head_icd_addendum_0.4.md` §2**: a duration from receipt. Please copy that sentence into the ICD table. | Sends the duration (`sync_expiry_s`). `HeadLinkConfig.sync_expiry_mode` keeps an `absolute_head_time` switch only for a non-conforming head. |
| CR-02 | Registry use `COMMISSIONING` | Add to the ICD/registry description: a third `authorized_uses` value between BENCH and SURVEY that allows mapping with CONCEPT geometry and a synthetic calibration, every product flagged `field_use_approved: false`. | Implemented host-side (`rr_core/descriptor.py`). SURVEY keeps the baseline rule (AS_BUILT, qualified limits, approved calibration). |
| CR-03 | Calibration `setup_id` binding | The demo calibration names `DEMO-SETUP-0`; the demo descriptor has `optic-test-01` and the native head `S1-…`. Decide whether a calibration must match the head `setup_id` exactly. | Mismatch is recorded in the attachment manifest (`calibration.setup_match: false`) and allowed in COMMISSIONING; `CalibrationStore(strict_setup=True)` refuses it. |
| CR-04 | Search alarm level | `survey_methods.SEARCH_THEN_COUNT` needs a profile field for the ratemeter alarm probability (sliding window evaluated every gate, four lanes). With the profile's `alpha_per_decision` = 0.05 the search stage alarms about every few seconds on a clean floor. | `MissionConfig.ratemeter_alpha` (default = profile alpha; scenarios use 1e-5). Also: the alarm fires on the leading edge of a spot, so the robot follows the window rate for ≤ 0.15 m (`peak_search_m`) before stopping, instead of "stops at once". |
| CR-05 | Step-and-count station pitch | `station_pitch_m: 0.10` equals the aperture length. With the credited footprint eroded by the position allowance *e* per side, stations leave 2·e-wide uncredited stripes (20 mm at e = 10 mm; measured in scenario s10). Pitch ≤ L − 2e (0.08 m) closes them. | **Accepted by the lead (contract `station_pitch_m: 0.080`).** The default now follows the contract (`geometry_config.survey_method_defaults` → MissionConfig; MissionConfig/PlanConfig fall-back 0.08); still a parameter (`mission.station_pitch_m`). Test `rr_bringup/test/test_config.py`. Scenario s10 keeps an explicit 0.10 m to document the stripes. |
| CR-06 | Wall strips and in-place turns | With the swept radius 0.278 m the outermost track is 0.298 m from a wall, leaving ~0.137 m unsurveyed along each wall (0.176 m on the narrow test floors is the same strip). A peel-off / reverse-entry lane change on the wall tracks would reduce this to about `head half-width + wall margin − 171 mm + e` ≈ 44 mm but needs arcs or diagonal reversing near the wall; decide whether that manoeuvre is wanted before it is built. | Not implemented; strips are planned residuals and are reported with location and area. **Logged by the lead as IB-29 (`docs/architecture/INTEGRATION_BACKLOG.md`), decision deferred.** |
| CR-07 | Along-track reference | Localisation gets x only from an end wall inside the LiDAR field (270°, blind to the rear) and range. With the doors open and the bulkhead beyond range, x is odometry only and credit is withheld once the 2σ budget (10 mm at the row) is exceeded. A removable target or closed doors is needed in long trailers; define the site rule. | `trailer.door_closed` parameter; the supervisor holds on `LOCALIZATION`. LiDAR range default 12 m is an assumption (no LiDAR datasheet value in the contract). **Logged as IB-30, decision deferred.** |
| CR-08 | Cell variance with fractional weights | MODEL.md §6 weights counts and live time by footprint fraction and §3 uses the Poisson form with the weighted sums. The weighted sum of Poisson counts has a smaller variance than a Poisson count of the same mean, so thresholds and D# computed per cell are conservative. Radiometry owner to confirm this is intended. | Implemented exactly as written; stated in the export manifest `assumptions`. **Logged as IB-31, decision deferred.** |
| CR-09 | Exact thresholds for a lane combination | MODEL.md §3 (R2) defines the exact threshold for one lane; §6 combines lanes. The exact distribution of a 4-lane weighted combination is not specified. | Per-lane exact threshold, combined in normal form with the common calibration terms added after combination; method string `poisson-exact-per-lane/normal-combination` stored per cell. Single-lane scaler counts use the exact threshold and an exact numerical detection limit. **Logged as IB-31, decision deferred.** |
| CR-10 | Rear field for reversing | The LiDAR cannot see behind the robot; the Expose-spot reverse relies on the chassis rear proximity field (`FIELD_REAR` / `DIR_INHIBITED`). The contract offset 0.35 m should be checked against the rear ToF stop distance in VT-035. | Host route check covers what the LiDAR sees; a refused/stopped reverse leaves the item open. |
| CR-11 | REP-105 odom frame | The robot node publishes `map → base_link` directly (fused pose); a separate continuous `odom` frame is published only by the stand-alone chassis bridge node. Say whether consumers need `map → odom → base_link`. | As described. **Logged by the lead for a later decision (with IB-29…31); nothing implemented.** |
| CR-12 | Chassis `STATE.brake_test` | The native emulator's STATE did not carry `brake_test` in the first reply after the test (possibly `truncated`). | The supervisor uses the `BRAKE_TEST` op result, not STATE. |
